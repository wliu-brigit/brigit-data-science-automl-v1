# Coder

Manual coder turn. Use `automl-coder` with fresh context to implement exactly one validated `Proposal`.

## Inputs

- `Proposal`: required `schema_version`, `slug`, `strategy`, `hypothesis`, `implementation_plan`, `constraints`, and `required_dependencies`; optional `rationale`, `evidence`, `data_checks`, `risk_notes`, and query-shaped `seed_hint` (`auto`, `best`, `latest`, or `strategy:<name>`). `implementation_plan`, `constraints`, and `required_dependencies` must be non-empty lists of strings; `constraints` must never be an object.
- `project_root`: absolute path to the project.
- `allowed_dependencies`: dependencies permitted by `pyproject.toml`.
- `data_context`: MLflow-derived active dataset metadata and optional profile enrichment.
- `project_contract`: normalized target column, raw target column, primary metric,
  and required project transformers.
- `dry_run`: when true, run the trial with `AUTOML_INHERIT_DRY_RUN=1`.
- `project_name`: active project under `<project_root>/projects/<project_name>`.

## Coder Scope

The coder may read only project instructions, config, active project data and query files, active project evaluation recipe, base model, feature registry, active training data, and the seed `model.py` already copied into the trial directory when present.

Allowed read list:

- `<project_root>/projects/<project_name>/PROJECT_INSTRUCTIONS.md`
- `<project_root>/projects/<project_name>/config.py`
- `<project_root>/projects/<project_name>/data/queries/base_data.sql` when present
- `<project_root>/projects/<project_name>/data/queries/training_data.sql` when present
- `<project_root>/projects/<project_name>/data/pipeline.py` when present
- `<project_root>/projects/<project_name>/eval/metrics.py` when present
- `<project_root>/automl/model/base.py`
- `<project_root>/automl/data/features.py`
- the trial directory's seed `model.py` when `trial.create` copied one; the coder rewrites it per the proposal

Before dispatching the coder, render the AutoML context for the same route and use its route-scoped proposal commands:

```bash
cd <project_root>
uv run "${CLAUDE_SKILL_DIR}/../automl/scripts/render_context.py" --project-root <project_root> --arguments "experiment run --project <project_name>"
```

Use `--arguments "experiment run --project <project_name>"` for normal work.
Use `--arguments "experiment run --project <project_name> --dry-run"` for
dry-run work. Run the rendered safe commands from `<project_root>` so relative
trial and cache paths resolve inside the active project.

The orchestrator must persist the validated proposal with `safe_commands.persist_proposal` from that rendered context:

```bash
<safe_commands.persist_proposal> <<'JSON'
<exact Proposal JSON>
JSON
```

The coder creates one trial directory with:

```bash
<safe_commands.create_trial>
```

The rendered dry-run command already includes `--dry-run`. It also includes `--project <project_name>`, which routes the run to the active project package. The proposal JSON is the source of truth for slug, strategy, seed hint, and hypothesis. The coder writes only the current trial's `model.py` and trial-owned scratch generated by scripts.

Run only the current trial:

```bash
cd <project_root>
uv run experiments/<TRIAL_ID>/run.py
```

For dry-run:

```bash
cd <project_root>
AUTOML_INHERIT_DRY_RUN=1 uv run experiments/<TRIAL_ID>/run.py
```

The coder must run the trial command directly. Do not use shell pipes, `tail`,
`|| true`, or wrapper commands that can mask a nonzero exit status. Long output
is handled by the runner's grep-friendly stdout markers and MLflow artifacts.

## Hard Rules

- Do not read test data directly.
- Do not read broad leaderboard context.
- Do not read unrelated past trial artifacts or broad MLflow leaderboard context.
- Do not edit framework files, `projects/<project_name>/config.py`, config, project instructions, prior trials, or `run.py`.
- Do not assume Snowflake or SQL. Use the project-local `projects/<project_name>/config.py`, active
  dataset context, and configured project data source as source of truth.
- If a missing package is needed, return JSON with `status="missing_dependency"` and `missing_package`.
- Return JSON only, with no markdown fence and no prose.

## Model Contract

Create `<TRIAL_DIR>/model.py` defining a `Model` class subclassing `BaseModel`.

Required:

- `name` class attribute.
- `fit(self, df_train, registry, seed=0)`.
- `transform(self, df)`.
- `_predict(self, X)`.
- `self.model`, `self.preprocessor`, and `self.feature_registry` set inside `fit`.

Do not override public inference methods: inherit `predict(context, model_input, params=None)` and `predict_transformed(X)` from `BaseModel`.
`predict` filters with `FeatureRegistry.select`, casts with `FeatureRegistry.cast`, then calls `transform` and `predict_transformed`.
Put estimator-specific scoring in `_predict(X)`: binary classifiers usually return `self.model.predict_proba(X)[:, 1]`; regressors usually return `self.model.predict(X)`.
Before writing the model, read `<project_root>/automl/model/base.py`; it is the full source-of-truth contract copied into the project.
Do not call `mlflow.log_*` from `model.py`. The runner owns MLflow artifact paths,
metrics, tags, and manifests. For model-specific training diagnostics such as CV
folds, selected hyperparameters, OOF summaries, category handling, or other
small JSON-serializable details, implement `training_report(self)` and return a
mapping; the runner logs it as `model/report.json`.
Do not serialize the model yourself. The runner logs the fitted `BaseModel` as
an MLflow pyfunc model after the trial command succeeds.

Model imports should start with:

```python
import copy

from automl.model import BaseModel
```

Model `fit` should start with:

```python
self.feature_registry = copy.deepcopy(registry)
feature_cols = self.feature_registry.get_by_flag("feature")
self.feature_registry.set_flag(feature_cols, "model", False)
# Select only columns consumed by the fitted estimator, then:
self.feature_registry.set_flag(self.feature_cols, "model", True)
```

Model prediction hooks should look like:

```python
def transform(self, df):
    return self.preprocessor.transform(df[self.feature_cols])

def _predict(self, X):
    return self.model.predict_proba(X)[:, 1]
```

Models must start from the dataset registry supplied by data loading. Do not rebuild the registry from `df_train`. Select model inputs from `registry.get_by_flag("feature")`. If removing a feature, preserve existing comments and append a concise model-side reason.
Use `project_contract.target_column` or `registry.get_by_flag("target")` for
labels; do not guess from raw source names such as `TARGET`.

If `project_contract.required_transformers` is non-empty, include the project
requirements returned by `self.required_transformer_entries()` in a top-level
`ColumnTransformer`. Include the required columns in `self.feature_cols`, leave
their registry entries `model=True`, and pass the training target into
`fit`/`fit_transform` so target-aware transformers can fit. Do not wrap required
transformers inside another transformer that hides them from validation.

## Result Handling

After running, use the direct command exit status plus stdout markers
(`AUTOML_STATUS=`, `AUTOML_PRIMARY=`, `AUTOML_TRIAL_ID=`, `AUTOML_RUN_ID=`) to
return status to the orchestrator. The runner writes durable trial state to
MLflow; local result JSON is not produced.

Expected successful trial files include:

- `metadata.json`
- `model.py`
- `proposal/trial_proposal.json`
- `manifest.json`
- `model/report.json` when `Model.training_report()` returns diagnostics
- `timing/summary.json`
- `eval/manifest.json`
- `eval/test/report.json`
- `eval/train/report.json`
- `features/feature_registry.csv`
- `validation/report.json`
- `logs/errors/report.json` and `logs/errors/traceback.txt` when the trial fails or crashes

## Return JSON

For success or ordinary trial failure:

```json
{
  "trial_id": "1_baseline",
  "run_id": "abc123",
  "status": "success",
  "primary": 0.71,
  "takeaway": "Baseline completed and logged to MLflow."
}
```

For missing dependencies:

```json
{
  "trial_id": "",
  "run_id": "",
  "status": "missing_dependency",
  "missing_package": "lightgbm",
  "takeaway": "Trial requires package lightgbm, which is not in allowed_dependencies."
}
```
